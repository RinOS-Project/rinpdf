# rinpdf

RinOS向けPDFライブラリ（開発中）。C++20、C ABI、Meson。zlibが必要です。

## 実装済み
- PDFヘッダー／バージョン判定、ファイル／メモリ読み込み
- ASCII文字列から単一ページPDF生成
- Classic xref、構文木、Catalog→Pages→Pageツリー
- stream境界、直接・間接/Length、FlateDecode
- ページ/Contents参照からのデータ抽出
- 実験的CPU矩形レンダラー：g、rg、re、f/F、n、q、Q（グレースケール・RGB・CMYK塗りつぶし、描画色の保存・復元）
- smoke、xref、lexer、value、stream、stream_object、rectanglesテスト

## 描画API
`rinpdf_render_page(document, index, width, height, rgba, stride)` は、classic xrefのページから/Contentsを読み取り、RGBAへ描画します。現状は `g`, `rg`, `k`, `re`, `f`, `F`, `n`, `q`, `Q` の限定的な矩形塗りつぶしに対応します。テキストや未対応命令を含む場合は `RINPDF_UNSUPPORTED` を返し、呼び出し元の出力バッファを変更しません。ページ座標のMediaBox変換に初期対応しました。回転・CropBox・ページリソースの継承は未対応です。

OS-CoreのLadybird/AquamarineにはPainterAquamarineのビットマップ・パス描画実装がありますが、rinpdfからの直接呼び出しはまだ未統合です。現段階では独立CPUラスタライズ結果をアプリ側で表示する構成です。

## 制限
矩形レンダラーは公開rinpdf_render_page APIに接続しました。座標変換、CropBox、フォント、画像、パス一般、グラフィックス状態、透明度、一般パス・画像・テキスト描画は未対応です。PDF数値やトークン処理は限定的です。xref stream、object stream、増分更新、暗号化なども未実装です。一般のPDF表示には使用できません。

/Contentsとレンダラーの接続、MediaBoxと座標変換、グラフィックス状態、一般パス描画、フォント。

## リソース制限
公開レンダリングAPIは一時RGBAバッファを64MiB以内に制限します。CMYKは単純なDeviceCMYK→RGB変換であり、ICCプロファイルや色管理には未対応です。MediaBox、文字、一般パス、Aquamarine連携も引き続き未実装です。

## MediaBox座標変換 (experimental)
ページまたは親Pages辞書の整数配列MediaBoxを取得し、RGBA出力解像度に合わせて矩形を線形変換します。PDFの左下原点をRGBAの左上原点へ変換します。実数座標、CropBox、Rotate、UserUnit、一般CTMにはまだ対応していません。未対応の文書はRINPDF_UNSUPPORTEDを返します。

## CTM（実験的）
CPU矩形レンダラーは `cm` による軸平行な拡大縮小・平行移動と `q` / `Q` によるCTM保存復元に対応します。回転、せん断、任意のアフィン変換、一般パス、CropBox、Rotateは未対応です。対応できない行列は描画成功とせず拒否します。実機およびビルド・テストの動作確認は未実施です。

## CropBox表示領域 (experimental)
`read_page_box` はページまたは親Pages辞書のCropBoxを継承し、MediaBoxとの交差領域をRGBA描画のビューポートとして返します。CropBoxがなければMediaBoxを使用します。交差領域が空なら描画を拒否します。座標は現状整数配列のみです。/Rotate、/UserUnit、実数のページ境界、一般パスの描画には未対応です。CropBox用回帰テストは追加しましたが実行未確認です。

## ページ回転 (experimental)
ページ／親Pagesの整数/Rotateを継承し、0/90/180/270度（360度で正規化）に対応します。RGBA出力は時計回りの回転として処理します。90/270度では内部ラスタライズ寸法を入れ替えます。非90度単位は拒否します。ページ回転の統合テストを追加しましたが、ビルド・実行は未検証です。一般パス・テキスト・画像描画は引き続き未実装です。

## 一般パスの初期実装 (experimental)
CPUレンダラーは `m` (move)、`l` (line)、`h` (close) と `f` (fill) による直線ポリゴンのスキャンライン塗りつぶしに限定対応しました。既存の軸平行CTMとRGB/CMYK色を利用します。曲線 `c/v/y`、ストローク `S/s`、複合パスの正確なPDF非ゼロワインディング規則、アンチエイリアス、クリッピングは未対応です。現在の塗りつぶしは偶奇スキャンライン方式の暫定実装で、PDF標準の `f` と完全互換ではありません。ビルド・テスト実行は未検証です。

## Cubic path support (experimental)
`c`、`v`、`y` による3次ベジェ曲線を各16直線セグメントへ近似し、既存のスキャンライン塗りつぶしに接続しました。曲線の精度は固定分割であり、拡大表示時の品質やPDFのワインディング規則を保証しません。ストローク `S/s`、アンチエイリアス、クリッピングは未実装です。ビルド・テスト実行は未検証です。

## CPUパス描画の処理量制限
ポリゴン塗りつぶしではラスタライズ対象の出力領域を最大1,048,576ピクセルに制限し、クリップ後の負の座標をunsignedへ直接変換しないよう修正しました。これは暫定的な保守的制限であり、一般的な高解像度PDFを描画できることを意味しません。未対応のストローク、アンチエイリアス、非ゼロワインディング規則は引き続き未実装です。ビルド・テストの実行は未検証です。

## Basic stroke (experimental)
`w`、`S`、`s` による単純な線幅付きストローク描画を追加しました。CPUで線分からの距離を判定してRGBAを塗ります。描画要求は1024×1024以内に限定し、非正の線幅を拒否します。線端・線結合は暫定的な距離判定であり、PDFの`J`・`j`・`M`、破線、ストローク専用色、複雑なCTM、アンチエイリアスは未対応です。ビルド・テストは未検証です。

## Stroking color state (experimental)
非ストローク色（g/rg/k）とストローク色（G/RG/K）を分離しました。q/Qは線幅と両方の色を保存・復元します。線端J・線結合j・miter limit M・破線dは引き続き未実装です。現状の線分描画は丸い距離判定に基づく近似で、PDF仕様のcap/joinと一致しません。ビルド・テストは未検証です。

## Stroke cap/join state (experimental)
`J` と `j` は現在の距離判定レンダラーが近似する丸端（1）・丸結合（1）だけを受け付け、それ以外は明示的に拒否します。`M` は有効範囲の値を保持しq/Qで復元しますが、miter結合の描画は未実装です。PDFの初期cap/join値（0）を正しく描ける段階ではありません。破線`d`、butt/square cap、bevel/miter joinは未対応です。ビルド・テスト未検証。

## Stroke caps (experimental)
`J` は0=butt、1=round、2=squareに対応しました。距離ベースのCPUラスタライザで線分方向の投影を用いて端の延長範囲を制御します。線結合 `j` は依然として丸結合のみ、破線 `d` とアンチエイリアスは未実装です。既定の線端設定や結合部のPDF仕様完全準拠は未検証です。ビルド・テスト実行は未確認です。

## Stroke work budget (experimental)
ストローク描画で各線分ごとに出力領域全体を走査するため、合計走査量を16,777,216ピクセルに制限しました。複雑なパスは描画を拒否します。これは暫定的なDoS対策であり、画面内の線分範囲だけを走査する最適化ではありません。j=0/2、破線d、miter joinは未対応です。ビルドとテストは未実行です。

## Clipped stroke rasterization (experimental)
各ストローク線分の拡張バウンディングボックスを出力画像にクリップし、その範囲だけを走査するよう改善しました。累積走査上限16,777,216ピクセルは維持します。画面外線分は0ピクセル処理として通過します。細い線分を多数含むパスでも全画面走査を避けますが、線結合や破線は引き続き未実装です。ビルド・テスト実行は未検証です。

## Fill rule validation (experimental)
`f*` による単一サブパスの偶奇塗りつぶしを受け付けます。複数サブパスを持つ `f` / `f*` は、現在のラスタライザーがグローバルなワインディング計算を実装していないため拒否します。単一の自己交差パスもPDF仕様との完全な一致は未検証です。一般的な複合パスの描画は今後の課題です。ビルドとテストの実行は未検証です。

## Compound winding fill (experimental)
複数サブパスと矩形を共通エッジ集合へ変換し、`f`/`F` は符号付き交差数による非ゼロワインディング、`f*` は偶奇規則で塗りつぶすよう変更しました。穴あきパスの両規則の違いをテストに追加しています。対象は最大1,048,576ピクセルで、アンチエイリアスや高解像度・複雑なPDFの互換性は未検証です。ビルドとテスト実行は未確認です。

## Clipping implementation status
`W` / `W*` の実装を検討しましたが、PDF仕様上はクリップの設定とパス終了を分離する必要があり、初期案は取り消しました。現在は両命令を未対応として拒否します。W n / W* nの回帰テストを追加しました。今後はclip maskとq/Q状態の管理、W/W*の遅延適用、塗りつぶし・ストローク双方へのクリップ適用をまとめて実装します。ビルド・テストは未検証です。

## Rectangular clipping (experimental)
`re W n` の矩形クリッピングに限定対応しました。クリップ領域は既存領域と交差させ、q/Qで保存・復元し、後続の塗りつぶしとストロークに適用します。一般パスのW、偶奇クリップW*、Wの後にn以外の終了命令を使う形式は未対応で拒否します。ピクセル境界は現状のサンプル中心による整数近似です。ビルド・テスト実行は未検証です。

## Rectangular W* support (experimental)
単一の軸平行矩形に限り `re W* n` を追加しました。この形状では偶奇規則と非ゼロ規則の結果が一致するため、既存の矩形クリップを再利用します。複合パスのW/W*は未対応です。クリップ確定前のq/Qも拒否し、状態不整合を防ぎます。ビルド・テスト実行は未検証です。

## Clip state regression hardening
W/W*からnまでの間にm/l/c/v/y/h/reでパスを変更する入力を明示的に拒否します。入れ子のq/Qクリップ復元、画像外クリップ、未確定パス変更のテストを追加しました。一般パスのW/W*はまだ未実装です。実行環境からGitHubのDNS解決ができず、ビルド・テストは未検証です。

## Shared path mask rasterizer (experimental)
`src/renderer/path_mask.cpp` に非ゼロ／偶奇ワインディングの共通マスク生成とマスク交差を追加し、既存の `f`/`f*` 塗りつぶし処理を共通ラスタライザーへ接続しました。最大1,048,576ピクセル、エッジ数と走査量に制限があります。現在のW/W*はまだ矩形クリップのままで、一般パスクリッピングへの統合は未完了です。ビルド・テスト実行は未検証です。

## General path clipping (experimental)
`W n` と `W* n` を直線／曲線サブパスの共有ラスタライズマスクに接続しました。既存の矩形クリップは高速なscissor方式を維持します。マスクは既存のマスクと交差させ、塗りつぶしとストロークへ適用し、q/Qで保存・復元します。現段階ではW/W*の後はnで終了する必要があり、クリップ指定後のパス追加も拒否します。アンチエイリアス、任意のCTM、一般的なPDFの完全互換性は未実装です。ビルド・テストのPASSは未確認です。

## Degenerate path handling
共通パスマスクで空パスおよびmove-onlyサブパスを空のカバレッジとして扱うよう修正しました。マスク単体の回帰テストを追加しました。描画全体のテストは未実行であり、一般PDF互換性は未保証です。

## Empty clipping paths
空パスに対する `W n` / `W* n` は描画可能領域が空のクリップとして処理します。move-onlyパスも同様です。`q` / `Q` による元のクリップ状態への復元をテストに追加しました。現時点でテストは実行未検証です。

## 2x2 antialias coverage (experimental)
`rasterize_path_coverage_2x` は既存のワインディングラスタライザーを2倍解像度で実行し、4サンプルから0〜255のカバレッジを返します。出力は最大262,144ピクセルです。境界の半ピクセルを検証するテストを追加しました。現段階では内部APIで、公開ページレンダラーのRGBA合成やクリッピングにはまだ接続していません。ビルドとテストは未実行です。

## RGBA antialias integration (experimental)
塗りつぶし `f` / `F` / `f*` を2×2カバレッジからRGBAへ合成するよう接続しました。最大262,144ピクセルでは2×2サンプルを使用し、それより大きい画像では既存の単一サンプルへ戻ります。既存のクリッピングマスクは二値で、ストロークは未AAです。アルファチャネルは不透明RGBAのままで、RGBだけをカバレッジ合成します。専用の境界ピクセルテストを追加しました。ビルドとテストは未実行です。

## Stroke antialiasing (experimental)
CPUストロークは262,144ピクセル以下の描画で各ピクセル2×2サンプルを評価し、RGBへカバレッジ合成します。大きな出力では従来の中心サンプル方式です。ストローク線分を順次合成するため、結合部で重なりがある場合は過剰な濃度になる可能性があります。クリッピングマスクは依然として二値で、完全なPDFストローク品質は未達です。回帰テストは追加しましたがビルド・実行は未検証です。

## Stroke coverage union (experimental)
ストロークの各線分はRGBAへ直接合成せず、2×2サンプルのビット集合を共有バッファへORで集約してから一度だけRGBAへ合成します。同じ線分の重複による過剰な濃度を避けます。既存の累積線分走査上限は維持します。結合スタイルやクリッピング境界は未完成です。ビルド・テスト実行は未検証です。

## Clip coverage antialiasing (experimental)
一般パスのW/W*クリッピングに2×2カバレッジを接続し、RGBAの塗りつぶし・ストローク合成時にクリップ被覆率を掛け合わせます。マスク同士の交差も8-bit被覆率の乗算に変更しました。262,144ピクセルを超える描画では二値カバレッジ（0/255）を使用します。矩形scissorの境界は従来通り整数サンプル近似です。ビルドとテストは未実行です。

## Unified rectangular clip coverage (experimental)
単一矩形 `re W n` / `re W* n` も共通マスクラスタライザーへ統合しました。矩形境界は一般パスと同じ2×2被覆率で描画されます。矩形とポリゴンで同じ形をクリップしたときの出力一致を検証するテストを追加しました。最大262,144ピクセルを超える場合は二値マスクへ戻ります。ビルド・テストは未実行です。

## Affine CTM path rendering (experimental)
`cm` で6成分のアフィン変換を合成し、m/l/c/v/y/reのパス構築へ適用します。回転・せん断された矩形は4頂点のポリゴンへ変換して共通の塗りつぶし・クリッピング処理へ渡します。既存の距離ベースストロークは任意のアフィンCTMに未対応のため、回転・せん断行列を伴うストロークを明示的に拒否します。線幅の一般変換、任意CTMでのストローク品質、実機表示は未完成です。ビルド・テスト実行は未検証です。

## Affine stroke rasterization (experimental)
任意の可逆CTMに対して、ストロークの被覆判定を逆変換後の座標系で行うよう変更しました。回転・せん断・非等方拡大縮小を対象とします。描画範囲は変換行列のFrobeniusノルムから保守的に見積もります。特異行列と、パス構築途中でのCTM変更は現在拒否します。既存の線端・線結合の近似制約は残ります。ビルド・テストは未実行です。

## Mixed CTM paths (experimental)
パス構築途中の `cm` を塗りつぶしとクリッピングに限り受け付け、各命令で変換済みの頂点を保持します。CTM変更を跨ぐストロークは、線幅や各セグメントのCTMを個別保持していないため引き続き拒否します。`n`、塗りつぶし、ストローク終了時に混在フラグを初期化します。対応範囲の回帰テストを追加しましたが、ビルド・テストの実行は未確認です。

## Graphics state and current path
PDFの現在のパスは `q` / `Q` のグラフィックス状態スタックには含まれません。`Q` でパスを破棄・拒否せず、構築済みの頂点を保持するよう修正しました。パス途中で `Q` によりCTMが切り替わる場合、塗りつぶしは変換済み頂点を維持し、ストロークは線幅のセグメント単位CTMが未整備のため拒否します。ビルド・テストの実行は未確認です。

## Per-segment stroke CTM snapshots (experimental)
パスの各頂点に構築時のCTM線形部を保存し、ストロークの各線分で終点側のCTMを使用して逆変換による線幅判定を行います。矩形パスにも構築時の行列を保持し、パス終了時にスナップショットを破棄します。パス途中でcmまたはq/QによりCTMが切り替わっても限定的に描画しますが、線幅やjoin/capのPDF仕様完全準拠は未保証です。テストは追加しましたが未実行です。

## Hairline stroke support (0.44.3)
PDFの `0 w` は無効な線幅ではなく、出力デバイス上の最小幅（hairline）を意味します。`w=0` を受理し、現在のCPUラスタライザーではデバイス座標で約1ピクセルの線幅となるよう逆CTMで幅を調整します。負の線幅は拒否します。これは簡易的なデバイス依存幅の近似であり、PDFレンダラー全体の仕様適合性を保証しません。テストを追加しましたが、GitHubのDNS解決に失敗し、ビルドと実行は未確認です。

## Join state parsing (0.44.4)
